# 证监会立案调查：为什么它是硬否决

> 这一页回答：这只票现在是不是正被监管盯着，而价格还没反应？

## 与财务红旗的区别

[FUNDAMENTALS.md](FUNDAMENTALS.md) 的红旗说的是**数字看起来不对**：负债高、利润没现金。
那是概率判断，可以给权重、可以打折。

立案调查不是。它说的是**这家公司已经进入了另一种状态**：

- 再融资、发行股份购买资产、重大资产重组都会被卡住；
- 银行抽贷、供应商改账期、审计师出保留意见的概率同时上升；
- 结局通常是财务追溯调整（restatement），最坏是退市。

所以这里没有分数、没有"中风险"——**要么在调查中，要么不在**。在，就默认不进名单。

## 数据从哪来：证监会官网没有这个栏目

最直觉的做法是去证监会官网查，但那里查不到：

| 想找的 | 官网实际情况 |
| --- | --- |
| 「正在调查」名单 | **不存在这个栏目** |
| 行政处罚 | 有「行政执法 > 行政处罚」栏目，但列表由 JavaScript 异步填充，静态页面没有条目 |
| 立案告知书 | 不在官网发布，由上市公司**自己公告** |

实测访问 `www.csrc.gov.cn/csrc/c101928/common_list.shtml`，返回的正文在「行政处罚」
标题之后直接进入友情链接区，没有任何条目。它不是一个可以程序化读的数据源。

所以改用**巨潮资讯**（cninfo）：法定信息披露平台，每一份立案告知书都必须从这里发出。
它支持按标题 + 日期范围检索，一年只要约 10 个请求：

```text
逐日扫全市场公告流    1 年 = 250 个交易日 ≈ 8 分钟
巨潮标题检索          1 年 = 10 个请求，实测 1.9 秒
```

差距不是优化，是可行性：8 分钟的一次性成本没人愿意付，1.9 秒可以每天跑。

## 状态是推导出来的

没有接口直接报告"当前是否在调查中"，只能从公告推：

```text
立案告知书 / 立案调查进展        → 调查开始（或仍在进行）
行政处罚决定书 / 终止调查 / 撤销立案  → 调查结束
```

一只股票算"调查中"，需要同时满足：

1. 最近一次「立案」之后**没有**任何「结案」公告；
2. 那次立案距评估日**不超过一年**（`regulatory.active_days`）。

第 2 条是必须的取舍。证监会没有法定期限，有案子查了三四年；一年短到可能漏掉
长期悬案，长到可能永久封杀一家早已悄悄了结的公司。选一年，是因为它偏向"宁可多排
一年"——漏掉一家在调查中的公司，代价比多排一家已经干净的公司大得多。

**「立案调查进展暨风险提示」也是有效信号**，不是噪音。65 条这类公告里，很多是
窗口外立案的老案子在定期报进展——那正是最该被排除的一批。列表里的日期是
「最近一次公告日」，不一定是最初立案日。

## 关键词：这里最容易做错

一年 368 条命中里，只有约四分之一是真的"公司在被证监会调查"。实测分类：

| 标题 | 判定 |
| --- | --- |
| `关于收到中国证监会立案告知书的公告` | ✅ 立案 |
| `关于公司及控股股东收到立案告知书的公告` | ✅ 立案（本体也涉及） |
| `关于控股股东、实际控制人收到立案通知书的公告` | ✅ 立案（见下） |
| `关于公司股东收到立案告知书的公告` | ⚠️ 股东，非本体 |
| `关于董事长收到立案告知书的公告` | ⚠️ 个人，非本体 |
| `关于控股子公司收到立案告知书的公告` | ⚠️ 子公司，非本体 |
| `关于买卖合同纠纷案立案受理的公告` | ❌ 法院受理 |
| `关于提起上诉案件受理立案暨诉讼的进展公告` | ❌ 法院受理（词序是反的） |
| `关于张宝被公安机关立案侦查的进展公告` | ❌ 公安刑事立案 |
| `关于副总经理被立案审查调查并留置的公告` | ❌ 纪委监委，不是证监会 |

四条硬规则：

1. **`调查` 完全不能用。** `尽职调查` 出现在每一份独立财务顾问意见里。
2. **`立案` 要挡三类同形词**：法院的 `立案受理` 与 `受理立案`（词序会反）、
   公安的 `立案侦查`、纪检的 `立案审查`。
3. **结案要分监管机构。** 财政部、税务局的《行政处罚决定书》不是证监会结案。
   把后者当成结案，等于给一家仍在被调查的公司开一张干净证明。
4. **别用 `公司关于` 判断主体。** 它匹配 `…控股子公司关于…` 和 `…公司关于…` 一样顺，
   一旦误判，子公司的案子会算成母公司的。

## 两档：本体排除，股东/高管只提醒

一年 209 条立案公告里，只有 95 条是公司本体被立案，其余是股东、高管、子公司。
把后者全算成"股票被调查"，会把一批正常经营的公司挡在策略外。

| 档 | 判据 | 处理 |
| --- | --- | --- |
| **本体**（硬排除） | 公司收到立案告知书；或**控股股东/实际控制人**被立案 | 不进名单 |
| **相关方**（软提示） | 一般股东（如 5% 以上）、董事、监事、高管、子公司被立案 | 列出，不排除 |

控股股东和实际控制人为什么算本体：他们的合规状态**直接卡住公司自己的**再融资和
发行股份购买资产——和公司被立案冻结的是同一件事。5% 股东的合规状态不卡。

四处读法：

- **76 只里大量 ST / \*ST**（\*ST纳川、ST椰岛、\*ST九鼎、\*ST卓然…），立案与财务
  恶化常常同源，但两套规则各自独立——财报可能显示"低风险"，监管却是"立案"。
- **实控人被立案（交建股份、祥源文旅、ST金鸿顺）按本体处理**，它们和公司被立案
  冻结的是同一批资本运作。
- **`*ST卓然` 的标题是「立案调查进展暨退市风险提示」**——进展公告说明案子在推进，
  不是结案。这类"进展"公告是老案唯一的线索，不能当噪音删掉。
- **`920000.BJ` 有立案但查不到财报**：北交所标的 baostock 覆盖有限，财报口径是
  「未知」，监管口径是「立案」——两个维度必须分开看，不能互相替代。

## 怎么用

```bash
quant-fundamentals --provider baostock            # 检索一年 + 特别提醒
quant-fundamentals --provider baostock --no-scan  # 不联网，只用已存事件
quant-fundamentals --provider baostock --as-of 2026-09-01   # 那天已公告的口径

quant-screen --provider baostock                  # 默认排除调查中的本体
quant-screen --provider baostock --allow-investigated       # 放行，查看完整名单
```

`quant-screen` 只读已存事件，**不联网**——检索是 `quant-fundamentals` 的职责。
如果从未检索过，选股会打警告而不是静默放行：

```text
WARNING 没有监管事件数据，立案过滤未生效。先运行：quant-fundamentals --provider baostock
```

## 扫描窗口之外的历史案件

检索窗口是一年。一家更早立案、至今悬而未决的公司，在窗口里是隐形的——而那恰好
最该排除。`config/regulatory.yaml` 补这个缺口：

```yaml
investigations:
  - symbol: 600000.SH
    date: 2025-06-01
    note: 涉嫌信息披露违法违规
  - symbol: 600001.SH
    date: 2025-06-02
    issuer: false          # 只有股东/高管被立案
```

有结案公告的会自动解除，不需要手工删。

## 边界

- **只认公告标题。** 标题写「重大事项」而正文才提立案的，抓不到。规则是字面匹配，
  不是语义理解。
- **一年有效期是猜的。** 案子拖过一年会被放行。宁可人工复核，也不要默认它已经干净。
- **两档判据是启发式的。** 「公司及控股股东」算本体、「公司股东」算相关方，靠标题
  字样区分。标题写得不规范时会分错档。
- **不覆盖交易所问询、会计差错更正、审计意见变更。** 它们同样预警，但需要另一类规则。
- **规则变更后要清库重建。** 事件库是累积的，改了判定规则后旧记录不会自动重判：
  `rm data/regulatory/events.parquet` 再跑一次。
