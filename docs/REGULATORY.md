# 证监会立案调查：为什么它是硬否决

> 这一页回答：这只票现在是不是正被监管盯着，而价格还没反应？

## 与财务红旗的区别

[FUNDAMENTALS.md](FUNDAMENTALS.md) 的红旗说的是**数字看起来不对**：负债高、利润没现金。
那是概率判断，可以给权重、可以打折。

立案调查不是。它说的是**这家公司已经进入了另一种状态**：

- 再融资、发行股份购买资产、重大资产重组都会被卡住；
- 银行抽贷、供应商改账期、审计师出保留意见的概率同时上升；
- 结局通常是财务追溯调整（restatement），最坏是退市。

所以这里没有分数、没有"中风险"——**要么在调查中，要么不在**。在，就默认不进名单。

## 没有"调查中名单"这个接口

免费数据里不存在"当前被证监会调查的公司"这个词条，能找到的只有**公告流**。
所以状态必须自己推导：

```text
立案告知书            → 调查开始
行政处罚决定书 / 结案 / 终止调查 / 撤销立案  → 调查结束
```

一只股票算"调查中"，需要同时满足：

1. 最近一次「立案」之后**没有**任何「结案」公告；
2. 那次立案距评估日**不超过一年**（`regulatory.active_days`）。

第 2 条是必须的取舍。证监会没有法定期限，有案子查了三四年；一年短到可能漏掉
长期悬案，长到可能永久封杀一家早已悄悄了结的公司。选一年，是因为它偏向"宁可多排
一年"——漏掉一家在调查中的公司，代价比多排一家已经干净的公司大得多。

## 关键词是这里最容易出错的地方

全市场一天三千条公告，"立案"一个月只命中个位数。实测（2026-10-08 至 10-31，
17 个交易日，34221 条公告）：

| 标题 | 判定 |
| --- | --- |
| `*ST纳川:关于收到中国证监会立案告知书的公告` | ✅ 立案 |
| `信宇人:关于收到中国证券监督管理委员会立案告知书的公告` | ✅ 立案 |
| `安徽凤凰:关于董事长收到中国证监会立案告知书的公告` | ✅ 立案 |
| `东睦股份:…买卖合同纠纷案立案受理的公告` | ❌ 法院立案，与证监会无关 |

真实立案在标题里一定带「立案」，但「立案」也会出现在**法院受理**里，所以
`立案受理`、`纠纷` 被排除。反过来，「调查」这个词完全不能用——
`尽职调查` 出现在每一份独立财务顾问意见里，一放开就是满屏误报。

同样的道理，**结案**也要区分监管机构：

```text
关于收到《行政处罚决定书》的公告          → 结案
关于收到财政部行政处罚决定书的公告        → 不是结案
```

财政部罚了不等于证监会查完了。把后者当成结案，等于给一家仍在被调查的公司
开了一张干净证明——这是这里唯一值得避免的错误方向。

## 扫描是增量的

一天的全市场公告要几十页请求、约三秒。所以已扫过的日期记在
`data/regulatory/scan_state.json`，之后只取新增：

```text
首次（60 天 → 42 个交易日）  42 个请求，实测 76 秒
之后每天                     1 个请求，约 2 秒
```

注意状态是按**扫描过的日期**记的，不是按"有事件的日期"。一个没有立案的日子
也是一个结果，不能因为没命中就每天重扫。

## 扫描窗口之外的历史案件要手工登记

扫描只看最近 `lookback_days` 天。一家 2024 年立案、至今悬而未决的公司，
在六十天的窗口里是隐形的——而那恰好是最该被排除的一类。

`config/regulatory.yaml` 补这个缺口：

```yaml
investigations:
  - symbol: 600000.SH
    date: 2025-06-01
    note: 涉嫌信息披露违法违规
```

有结案公告的会自动解除，不需要手工删。

同一批名单在选股里是这样被挡住的：

```text
WARNING 14 只处于证监会调查中，已排除：002253.SZ, 002361.SZ, 300086.SZ, …
```

四处读法：

- **14 只里有 4 只是 ST / \*ST**（\*ST纳川、\*ST卓然、ST椰岛、ST合纵），立案与财务
  恶化常常同源，但两套规则各自独立——财报可能显示"低风险"，监管却是"立案"。
- **三只是「高管/董事长收到立案告知书」**（安徽凤凰、神剑股份、科力远的部分情形），
  公司本身未必被立案。这里仍然排除：实际控制人被查期间，公司的资本运作同样停摆。
- **`*ST卓然` 的标题是「立案调查进展暨退市风险提示」**——进展公告说明案子在推进，
  不是结案。规则按标题判"立案"，不会把它误当成结束。
- **`920000.BJ` 有立案但查不到财报**：北交所标的 baostock 覆盖有限，财报口径是
  「未知」，监管口径是「立案」——两个维度必须分开看，不能互相替代。

## 怎么用

```bash
quant-fundamentals --provider baostock            # 扫描增量 + 特别提醒
quant-fundamentals --provider baostock --no-scan  # 不联网，只用已存事件
quant-fundamentals --provider baostock --as-of 2026-09-01   # 那天已公告的口径

quant-screen --provider baostock                  # 默认排除调查中的
quant-screen --provider baostock --allow-investigated       # 放行，查看完整名单
```

`quant-screen` 只读已存事件，**不扫描**——扫描是 `quant-fundamentals` 的职责。
如果从未扫描过，选股会打警告而不是静默放行：

```text
WARNING 没有监管事件数据，立案过滤未生效。先运行：quant-fundamentals --provider baostock
```

## 边界

- **只认公告标题。** 标题写"重大事项"而正文才提立案的，抓不到。规则是字面匹配，
  不是语义理解。
- **覆盖窗口有限。** 首次只回看 60 天。用之前先跑几周，或把已知案件写进手工名单。
- **一年有效期是猜的。** 案子拖过一年会被放行。宁可人工复核，也不要默认它已经干净。
- **不区分调查对象。** 公司被立案、董事长被立案、控股股东被立案，这里一视同仁。
  严格说这三者的严重程度不同，但没有结构化字段可以区分。
- **不覆盖交易所问询、会计差错更正、审计意见变更。** 它们同样预警，但需要另一类规则。
