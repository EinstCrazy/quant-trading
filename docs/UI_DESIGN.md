# 界面设计 Web UI

研究工作台的外壳。定位是**编排与展示**，不是第二个计算引擎。

## 定位与四条原则

1. **界面不发明计算。**
   所有数字——指标、净值、成本、质量报告——都由 `quant_research` 现有函数产出
   （`load_price_panel`、`describe_panel`、`run_backtest`、`summarize`）。
   界面只做参数编排与渲染。若界面自己算一次夏普，就会出现「界面里的回测」和
   「研究里的回测」两套数，这是必须避免的。

2. **后端无状态。**
   没有数据库。所有状态都在磁盘：`data/`、`config/settings.yaml`、`data/raw/<provider>/_state.json`。
   进程重启不丢任何东西，也不需要迁移脚本。

3. **只读优先。**
   第一个版本只有一条写路径：触发采集（`POST /api/collection/collect`）。
   回测、对比、预览都是纯读。

4. **零构建前端（第一版）。**
   单个 `index.html` + 原生 JS + 手写 SVG，不引入 Node、不引 CDN。
   代价是页面规模受限（见「取舍」），换来的是 `pip install && 打开浏览器` 就能跑，
   且在无外网环境可用。

## 架构

```text
浏览器（原生 JS + SVG）  ──fetch──  FastAPI  ──调用──  quant_research.{data, backtest, metrics, collector}
                                       │
                                       └── 只读/写  data/、config/、reports/
```

| 层 | 目录 | 职责 | 明确不做 |
| --- | --- | --- | --- |
| 前端 | `web/static/index.html` | 取数、渲染、交互 | 不计算任何指标，不缓存真相 |
| 路由 | `web/api.py` | 参数校验、编排库调用、序列化 | 不含业务逻辑 |
| 契约 | `web/schemas.py` | pydantic 请求/响应模型 | — |
| 应用 | `web/app.py` | `create_app()`、挂载静态资源 | — |
| 计算 | `data/`、`backtest/`、`metrics/`、`collector.py` | 唯一真相来源 | — |

前端通过 `/api` 拿 JSON；后端返回的是**降采样后**的序列（不是完整 DataFrame），
因此大区间也不会把浏览器打垮。

## 信息架构

九个视图，左侧切换，右侧内容区。

```text
┌──────────┬─────────────────────────────────────────────┐
│ 量化工作台 │                                             │
│          │                                             │
│ ▸ 数据    │  ① 数据：元信息卡 → 质量报告 → 走势 → 预览表  │
│ ▸ 回测    │  ② 回测：参数表单 → 净值/回撤图 → 指标 → 流水 │
│ ▸ 对比    │  ③ 对比：变体表 → 多曲线叠加 → 指标并排       │
│ ▸ 采集    │  ④ 采集：状态卡 → 标的清单 → 补数表单         │
│ ▸ 建议    │  ⑤ 建议：打分表单 → 今日名单 → 历史复盘       │
│ ▸ 指标    │  ⑥ 指标：说明目录 → 截面状态 → 单只查询       │
│ ▸ 自选    │  ⑦ 自选：添加行 → 分类过滤 → 清单表           │
└──────────┴─────────────────────────────────────────────┘
```

**① 数据**——回答「我手上这份数据能不能用」
数据元信息（来源、区间、标的数、复权口径、缺失策略）；
质量报告（`describe_panel`：缺失率、非正价格、异常跳变、日期单调性）；
价格走势（多标的归一化曲线）；尾部预览表。

**② 回测**——回答「这个策略值不值得再迭代」
参数表单（数据集、策略、窗口、权重方法、成交价、成本、约束、换手控制）；
净值曲线（策略 vs 等权买入持有基准）；回撤面积图；指标表；成本与换手；交易流水。

**③ 对比**——回答「哪组参数更稳」
在基线配置上叠加若干变体（改动窗口/权重方法/约束/换手），并排展示指标与曲线。
变体必须手动添加；另有一张「参数网格」卡做粗筛（上限 200 组，每组都进台账）。

**④ 采集**——回答「数据到哪了、要不要补」
每个 provider 的落盘状态（标的数、各自区间、行数）、失败清单、上次成功运行日期；
补数表单（数据源、范围、标的、起止、全量开关）→ 触发一次 `collect_once`。

范围可选**指定标的**或**全市场**：全市场会先向数据源拉取全部标的再逐只下载，并强制
按 ≥0.35 秒间隔节流（详见 [DATA_COLLECTION.md](DATA_COLLECTION.md) 的全量下载章节）——
几千只标的连着请求同一个主机，正是被判定为爬虫并切断的典型方式。界面因此在勾选全市场
时明确写出预计耗时，并说明可在任务面板随时取消、中断后从断点续采。

**⑤ 建议**——回答「今天该看哪几只，以及以前的建议到底行不行」

打分表单（数据源、选几只、最少历史、回放日期）提交为后台任务；名单卡给排名、分数与
等权权重；复盘卡按「次日开盘买入、持有 N 个交易日」回放每次名单，与回测用同一套成交
假设，这样台账和回测量的是同一件事。

名单卡上同时写**名单日期**与**数据截至日**：盘前打开时，前者是昨天，后者也是昨天，
一眼能看出这份名单不是今天的——没有日期的名单最容易被误读。回放的名单标为「历史」。

两条刻意保留的克制：一天选不满就少给几只，不为了凑数列满；刚跑完的名单不进复盘统计，
因为持有期还没走完。

**⑥ 指标**——回答「这些技术指标现在是什么状态」

面板给每个指标最后一根 K 线的截面（中位数与区间）和它的说明：名称带周期（`RSI(14)`
而不是「RSI」）、量纲、常见区间、一句建议读法；悬停看完整说明与误读提醒。说明文字不在
前端硬编码，由后端的指标目录（`indicators.catalog()`）提供，与 `docs/INDICATORS.md`
同源——否则代码改了口径、界面还念着旧词。

三处克制：**价格量纲不显示区间**（MA/BOLL/ATR 的 3.28 ~ 1356.54 是不同价位的票放在
一起求范围，没有意义，留空比给一个误导性的数字好）；**不给「买/卖」标签**（指标不含
仓位、成本与风险预算）；**首次打开自动算一次**（复用面板缓存，不必先跑命令行），之后
直接读盘，只有点「重算」才重跑。

单只查询把截面拆开：一只票的 26 个指标并排列出，这是「它为什么排在这个位置」的原料。
再往下是可调窗口（默认 120 天）的曲线，四个面板分开画：价格与布林带、RSI、MACD、KDJ。
分开画不是为了好看——RSI 在 0–100、价格在几元到上千元，硬放在一张图上就得双纵轴，而
双纵轴上的交叉几乎总是巧合。图上三处不将就：预热期的空值断线（当成 0 画会凭空出现一段
暴跌）、MACD 柱画成柱（看的是哪一侧，不是斜率）、RSI/KDJ 画出 20/80 参考线。

**⑦ 自选**——回答「我关心的票现在怎么样」

自选是用户标注的集合，不是行情的缓存：JSON 只记代码、名称、分类、备注，最新收盘与
日涨跌每次从面板现读——存下来的报价迟早是旧的，而旧报价读起来就是行情。一只票可属
多个分类；删除分类时引用一并摘除，不留悬空标签。加入入口有两处：本视图的添加行
（支持裸代码与中文名），以及指标详情页的「加入自选」——在那里加入时不问分类，一步
只做一件事，标签回自选页整理。各列表（建议名单、成交明细、落盘清单）里已在自选的
代码前有 ★：标注集合的意义就是让熟悉的票在别处一眼认出来。

自选页顶部是两层分析：

**大盘分析**——宽度统计加等权指数曲线（近 60 日，首日归一化到 100）。这里的「大盘」
只能诚实地叫作「已落盘样本的等权统计」：项目没有接指数行情，拿 30 只票的均值冒充
上证指数是编造。样本范围标注在标题旁——宽度数字的价值在于相对变化（涨跌家数、
MA20 之上占比、20 日新高新低），不在于和官方指数对数。没有自选股时这张卡照样可看。

**板块异动**——近 1/3/5/10 日各板块成分股的等权涨幅与上涨占比，领涨/领跌取相对排名
的两端：普涨日的 1% 领涨毫无信息，排分布两端才值得看。板块归属来自行业表
（`quant-symbols --sectors`），未建立时给建立命令——空表算出的「无异动」和真无异动
是两回事。自选清单与指标详情页都带板块标签：知道一只票属于哪个板块，是理解「它
为什么动」的一半。

**自选概览**——汇总（上涨/下跌、平均涨幅 vs 样本中位）与每只票的技术截面：RSI(14)
数值与状态、收盘在 MA20 之上/之下。超买/超卖只报状态不下结论——70/30 是参考线，
不是买卖信号，这个原则与指标页一脉相承。

**最近大事件**——近 5/10/20/30 日的时间线，检测四类行情异常：市场普涨普跌
（日中位 ±2%）、板块集体异动（等权 ±3% 且 ≥65% 成分同向）、个股暴涨暴跌
（单日 ±7%）、创 60 日新高/新低。项目没有新闻源，「大事件」就诚实地定义为
行情本身可验证的异常，不假装知道新闻。两个刻意设计：连续新高只报第一次——
趋势不是事件，每天报会把事件列表淹没成噪音；每条市场事件自带样本数——
「普跌：中位 -2.8%（样本 1 只）」自己就承认了没有说服力。

**⑧ 持仓**——回答「我拿的这些票，明天该盯什么」

成本与股数是用户录入的（`data/holdings.json` 账本），现价、盈亏、技术状态每次从
面板现读——存下来的价格永远是过期的价格。复盘把每只持仓归到**互斥的一档**：

| 档位 | 触发条件（先风险后机会，顺序即优先级） |
| --- | --- |
| 止损区 | 浮亏超阈值 **且** 收盘跌破 MA20 |
| 减仓观察 | 浮亏超阈值但仍在 MA20 上方 / 超买且贴着 20 日高点 / 收盘同时低于 MA20 与 MA60 |
| 止盈区 | 浮盈超阈值 **且** RSI 极端超买 |
| 观察 | 跌破 MA20，但 MA60 尚未失守 |
| 持有 | 收盘在 MA20 上方，其余条件不成立 |
| 数据不足 | 面板里没有这只票，或历史不足两天 |

每档给三样东西：一句结论、为什么（逐条依据，带具体数字）、**明日应关注的具体价位**
（成本线、MA20/MA60、ATR 止损参考 = 收盘 − 2×ATR、20 日高低）。「明天怎么办」落成
几个可核对的数字，而不是一句感觉。三条克制：**不预测**（规则只描述状态）、
**不下指令**（「止损区」的意思是「亏损已超阈值且趋势坏了」，不是「必须卖」——仓位
大小、资金性质、你的判断不在数据里，也不该假装在）、**阈值可改**（`settings.yaml`
的 `review:` 节：止损线、止盈线、超买线、贴前高的距离、ATR 倍数）。

组合层只给一句话，先说风险：有仓位处于止损区时，「N 只处于止损区——明天的第一
件事是它们，不是涨幅榜」；否则报告结构状态。数据缺一块就少一条依据（ATR 要
high/low，量比要 volume），分析照常，而不是整段失败。

**情景预案**——每只持仓给 2–3 条 if-then：「放量跌破 MA20 1307.52 → 转观察」、
「放量突破 20 日高 1392.05 → 止损上移但不追高加仓」、「缩量横盘在 MA20 下方 →
不动」。预案不是预言，是把「盘中临时拍脑袋」提前到收盘后冷静的时候做。三条
纪律：每条必须带具体价位（没有数字的「跌破支撑」等于没说）；缺失的价位让
对应条目直接不生成，而不是显示「跌破 MA20 —」；预案按档位给不同剧本——
止损区的剧本是「减到能承受的部分」，持有档的剧本是「回踩不动」，同一句
话术套所有情况就是没有话术。

**组合纪律检查**——与个股观点无关的结构性硬规矩：单一持仓集中度（超过
`max_single_pct` 参考线 warn、1.5 倍 fail）、风险档占比（止损/减仓观察
在持仓中的比例）、止损区仍有仓位（点名）、浮亏超 20% 的重亏仓位（回头
看买入理由）、数据完整性（取不到行情的仓位让复盘不完整）。全过时给一条
明确的「通过」项，而不是沉默——检查跑过和检查没跑是两回事。

**⑨ 板块**——回答「哪些板块在动、里面是谁在动」

两个层次：**板块一览**（等权 N 日涨幅、上涨占比、中位涨幅、分化度、当日
成交额、领涨/领跌各前 3），**点板块下钻**到成分股（当日/N 日涨幅、相对
板块的超额、RSI、MA20 上下、量比、成交额）。三个设计点：

- **等权与中位并给**：权重股拉板块指数时，中位数告诉你「多数人」的体验，
  两个数字差得远本身就是信息；
- **分化度**（板块内涨幅的标准差）：高 = 内部差异大，选股比选板块重要；
  低 = 齐涨齐跌，板块本身更有意义。这比一个板块涨幅数字有用得多；
- **不编样本外的东西**：单票板块不显示「领涨/领跌」（n≤1 显示 —），
  覆盖率（`n_covered/n_symbols`）如实标注——30 只票的「板块涨幅」不是
  行业指数，别拿它当。没有新闻源就不猜驱动，只描述结构。

数据前提是 `quant-symbols --sectors` 建好的行业归属表；未建时 400 并给出
命令，空表算出来的「板块无异动」和真无异动是两回事。页内可选数据源
（baostock/akshare）——分析必须落在实际有行情的那份面板上。

**复盘存档与对比**——「存为今日复盘」把当天结论写成
`data/reviews/{as_of}.json`（档位、收盘、盈亏率；同一天重复保存覆盖）。
下次打开时对比上一次存档：「与上次复盘（2026-11-07）相比：1 只档位变了」，
变化的那只在卡片里标「上次观察 → 现在止损区」。存档是显式动作，不是 GET
的副作用——界面不该悄悄改写数据；而复盘的本质就是对比，不存档就只剩
「今天感觉如何」。

### 长任务

回测与采集不能在请求线程里跑：全市场补数要几分钟，浏览器只会表现为卡住。
因此每条慢路径都有一个 `/api/jobs/...` 版本：

```text
POST /api/jobs/backtest  ──202──>  {id}  ──轮询──>  GET /api/jobs/{id}  ──>  status/progress/result
                                          DELETE ──>  协作式取消
```

- 同步端点（`/api/backtest`、`/api/collection/collect`）保留：小面板 0.3 秒的任务不值得排队；
- 任务在两线程池里执行，`progress` 给出 `done/total`，采集按标的、对比按组推进；
- 完成后结果归档到 `reports/webui/<id>_<kind>.json`，进程内保留最近 50 条；
- **重启后列表不丢**：启动时从归档目录读回任务，只恢复元数据（每条几百字节），
  点开某个任务时才把结果从磁盘读出来——长历史因此不占内存，条目上标"归档"；
- 每晚的采集也写一份 JSON 到 `reports/collection/`，采集页直接列出最近 10 次
  （更新 / 跳过 / 失败 / 新增行 / 失败标的），"昨晚到底跑没跑成"不用再开文件看；
- 失败的任务记录 `error`，不影响其它任务；worker 不会因异常退出。

### 实验台账

任务历史回答"我提交过什么"（按时间、按 id）；实验台账回答"我试过什么"（按配置、按结果）。
两者都要有：前者能重开一次运行，后者能在五十次尝试里挑出值得重开的那两次。

每次回测结束——同步端点与任务端点都算——往 `reports/experiments/index.jsonl` 追加一行：
配置（数据集、策略、参数、权重、换手）、关键指标、终值、笔数、成本，以及能打开完整结果的
`job_id`。曲线与流水不复制一份：它们留在任务结果里，台账只留比得过的那一屏。

- 排序按指标（夏普 / 年化 / 最大回撤 / 卡玛）；**算不出来的指标沉到底部，不伪装成 0**；
- 备注是台账的意义：数字记录结果，备注记录为什么放弃它；
- 对比页的"载入"把历史实验变成本次的对比变体——翻旧账是为了接着用，不是为了怀旧。

### 参数网格

二十组配置意味着二十次点击、二十次机会打错一个数字，而且不留记录。网格一次提交跑完
所有组合：每组都进实验台账，表格按指定指标排名，最优那行可一键载入为对比变体。

- **上限 200 组，提交前就校验**：200 次回测是几分钟，20000 次是一整夜，而两者的差别
  只是一个按键。超限时在开始之前拒绝，而不是跑了半小时才停。
- 权重方法也是一个维度（可多选），与参数做笛卡尔积；只有方法确实在变时，配置名才带上
  方法名——否则每行都写"等权"，参数本身反而更难读。
- **它是粗筛，不是优化器**：网格能指出值得细看的区域；用自己的最优结果给一次扫描排名
  会高估那个结果（多样本下的最大值不是期望）。所以每行都留档，供事后检验而非直接采信。

### 数据集寻址

不接受任意路径。后端启动时扫描出注册表，前端只传**键**：

- `sample:<stem>` → `data/sample/<stem>.csv`
- `raw:<provider>` → `data/raw/<provider>/daily`

既避免路径遍历，也让"这份数据是什么"始终可见。

## 关键实现决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 计算位置 | 全部在库里，接口只序列化 | 避免两套真相 |
| 状态存放 | 磁盘，无数据库 | 重启无损、无需迁移、与研究文件同一真相 |
| 写操作 | 只有采集一条 | 界面不该悄悄改写数据 |
| 前端构建 | 无（原生 JS + SVG） | 离线可用、安装成本低；规模失控时再引入 Vite |
| 图表库 | 手写 SVG path | 不引 CDN，内网可用；曲线需求只有折线与面积 |
| 长任务 | 线程池任务 + 轮询 | 慢任务不能占住请求线程，详见「长任务」 |
| 并发 | 不做保护 | 触发采集有进程内锁的余地，但第一版先明确「单用户工具」 |
| 视图状态 | URL hash（`#/watchlist`、`#/indicators/600519.SH`） | 刷新与前进后退可还原；详情页代码链接可复制分享。hash 相同不重复加载 |
| 表格排序 | 点击表头，前端重排已渲染行 | 不回服务端、不重渲染、不碰数据源；纯数字列（含 %、千分位）按数值，其余按文本 |
| 事件与自选 | 交集高亮 + 「只看涉及自选」开关 | 事件列表最长 80 条时，与自己的持仓/观察池的关联是最有价值的信息 |
| 持仓复盘 | 规则分档 + 描述性话术 | 数据里没有预测能力；给状态与关键价位，决定权留在人手里 |
| 情景预案 | if-then 而非预测 | 把盘中的临时决策提前到收盘后冷静做；每条预案必须带价位，缺值就不生成 |
| 复盘存档 | 每天一份 JSON，显式保存 | 复盘=对比；存档只留结论，行情仍现读。GET 不写盘，写操作仍只有用户点的按钮 |
| 板块分析 | 等权+中位+分化度，不编驱动 | 没有新闻源就不猜原因；分化度高说明选股比选板块重要，比一个板块涨幅数字有用 |

## 取舍与限制（诚实清单）

- **队列是单进程的**：线程池 + 内存状态，多进程部署需要真正的队列（Celery / RQ）。
  重启后列表从归档读回，但只有本进程跑过的任务才有实时进度。
- **取消是协作式的**：`DELETE /api/jobs/{id}` 只置位一个标志，正在进行的那一次请求仍会跑完。
  实测 1500 标的的补数在取消后于第 1 个标的位置停下——不是立刻，但不会继续拉完 1500 个。
- **前端无框架**：三个视图约 400 行 JS 是可维护的上限；再加视图就该引入构建与组件化。
- **无作业队列、无进度反馈**：采集补数请求可能跑几十秒，期间无进度条。
- **无用户/权限**：默认只监听 `127.0.0.1`。暴露到局域网等于把本地数据和采集能力开放出去。
- **不做参数搜索 UI**：只支持手动列举变体，避免一键过拟合。
- **无实验归档浏览**：`reports/` 目前只有采集报告 JSON，实验归档（批次 I）尚未落地。
