# 界面设计 Web UI

研究工作台的外壳。定位是**编排与展示**，不是第二个计算引擎。

## 定位与四条原则

1. **界面不发明计算。**
   所有数字——指标、净值、成本、质量报告——都由 `quant_research` 现有函数产出
   （`load_price_panel`、`describe_panel`、`run_backtest`、`summarize`）。
   界面只做参数编排与渲染。若界面自己算一次夏普，就会出现「界面里的回测」和
   「研究里的回测」两套数，这是必须避免的。

2. **后端无状态。**
   没有数据库。所有状态都在磁盘：`data/`、`config/settings.yaml`、`data/raw/<provider>/_state.json`。
   进程重启不丢任何东西，也不需要迁移脚本。

3. **只读优先。**
   第一个版本只有一条写路径：触发采集（`POST /api/collection/collect`）。
   回测、对比、预览都是纯读。

4. **零构建前端（第一版）。**
   单个 `index.html` + 原生 JS + 手写 SVG，不引入 Node、不引 CDN。
   代价是页面规模受限（见「取舍」），换来的是 `pip install && 打开浏览器` 就能跑，
   且在无外网环境可用。

## 架构

```text
浏览器（原生 JS + SVG）  ──fetch──  FastAPI  ──调用──  quant_research.{data, backtest, metrics, collector}
                                       │
                                       └── 只读/写  data/、config/、reports/
```

| 层 | 目录 | 职责 | 明确不做 |
| --- | --- | --- | --- |
| 前端 | `web/static/index.html` | 取数、渲染、交互 | 不计算任何指标，不缓存真相 |
| 路由 | `web/api.py` | 参数校验、编排库调用、序列化 | 不含业务逻辑 |
| 契约 | `web/schemas.py` | pydantic 请求/响应模型 | — |
| 应用 | `web/app.py` | `create_app()`、挂载静态资源 | — |
| 计算 | `data/`、`backtest/`、`metrics/`、`collector.py` | 唯一真相来源 | — |

前端通过 `/api` 拿 JSON；后端返回的是**降采样后**的序列（不是完整 DataFrame），
因此大区间也不会把浏览器打垮。

## 信息架构

四个视图，左侧切换，右侧内容区。

```text
┌──────────┬─────────────────────────────────────────────┐
│ 量化工作台 │                                             │
│          │                                             │
│ ▸ 数据    │  ① 数据：元信息卡 → 质量报告 → 走势 → 预览表  │
│ ▸ 回测    │  ② 回测：参数表单 → 净值/回撤图 → 指标 → 流水 │
│ ▸ 对比    │  ③ 对比：变体表 → 多曲线叠加 → 指标并排       │
│ ▸ 采集    │  ④ 采集：状态卡 → 标的清单 → 补数表单         │
└──────────┴─────────────────────────────────────────────┘
```

**① 数据**——回答「我手上这份数据能不能用」
数据元信息（来源、区间、标的数、复权口径、缺失策略）；
质量报告（`describe_panel`：缺失率、非正价格、异常跳变、日期单调性）；
价格走势（多标的归一化曲线）；尾部预览表。

**② 回测**——回答「这个策略值不值得再迭代」
参数表单（数据集、策略、窗口、权重方法、成交价、成本、约束、换手控制）；
净值曲线（策略 vs 等权买入持有基准）；回撤面积图；指标表；成本与换手；交易流水。

**③ 对比**——回答「哪组参数更稳」
在基线配置上叠加若干变体（改动窗口/权重方法/约束/换手），并排展示指标与曲线。
刻意**不做参数网格搜索**：一键扫 100 组参数只会让过拟合更好看。变体必须手动添加。

**④ 采集**——回答「数据到哪了、要不要补」
每个 provider 的落盘状态（标的数、各自区间、行数）、失败清单、上次成功运行日期；
补数表单（标的、起止、全量开关）→ 触发一次 `collect_once`。

## API 契约

全部前缀 `/api`，请求与响应均为 JSON。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 存活与版本 |
| GET | `/api/datasets` | 可用数据集清单（扫描 `data/sample/*.csv` 与 `data/raw/*/daily`） |
| GET | `/api/datasets/{key}/overview` | 元信息 + 质量报告 + 走势 + 预览表 |
| POST | `/api/backtest` | 运行一次回测，返回曲线、指标、流水 |
| POST | `/api/backtest/compare` | 基线 + 若干变体，返回各自的指标与曲线 |
| GET | `/api/collection/status` | 各 provider 的落盘状态与失败清单 |
| GET | `/api/collection/reports` | 归档的采集报告（每晚一份 JSON），倒序列出 |
| POST | `/api/collection/collect` | 触发一次采集（`dry_run` 可试运行） |
| POST | `/api/jobs/backtest` | 提交回测任务，立即返回 202 + job id |
| POST | `/api/jobs/compare` | 提交对比任务 |
| POST | `/api/jobs/collect` | 提交采集任务 |
| GET | `/api/jobs` | 最近任务（不含结果载荷） |
| GET | `/api/jobs/{id}` | 任务状态、进度、结果与错误 |
| DELETE | `/api/jobs/{id}` | 请求取消一个尚未结束的任务 |
| POST | `/api/jobs/grid` | 提交参数网格扫描，每组跑完都进实验台账 |
| GET | `/api/experiments` | 实验台账：跑过的配置与指标，可按指标排序 |
| PATCH | `/api/experiments/{id}` | 给一条实验加标签或备注 |
| DELETE | `/api/experiments/{id}` | 删除一条实验记录 |

### 长任务

回测与采集不能在请求线程里跑：全市场补数要几分钟，浏览器只会表现为卡住。
因此每条慢路径都有一个 `/api/jobs/...` 版本：

```text
POST /api/jobs/backtest  ──202──>  {id}  ──轮询──>  GET /api/jobs/{id}  ──>  status/progress/result
                                          DELETE ──>  协作式取消
```

- 同步端点（`/api/backtest`、`/api/collection/collect`）保留：小面板 0.3 秒的任务不值得排队；
- 任务在两线程池里执行，`progress` 给出 `done/total`，采集按标的、对比按组推进；
- 完成后结果归档到 `reports/webui/<id>_<kind>.json`，进程内保留最近 50 条；
- **重启后列表不丢**：启动时从归档目录读回任务，只恢复元数据（每条几百字节），
  点开某个任务时才把结果从磁盘读出来——长历史因此不占内存，条目上标"归档"；
- 每晚的采集也写一份 JSON 到 `reports/collection/`，采集页直接列出最近 10 次
  （更新 / 跳过 / 失败 / 新增行 / 失败标的），"昨晚到底跑没跑成"不用再开文件看；
- 失败的任务记录 `error`，不影响其它任务；worker 不会因异常退出。

### 实验台账

任务历史回答"我提交过什么"（按时间、按 id）；实验台账回答"我试过什么"（按配置、按结果）。
两者都要有：前者能重开一次运行，后者能在五十次尝试里挑出值得重开的那两次。

每次回测结束——同步端点与任务端点都算——往 `reports/experiments/index.jsonl` 追加一行：
配置（数据集、策略、参数、权重、换手）、关键指标、终值、笔数、成本，以及能打开完整结果的
`job_id`。曲线与流水不复制一份：它们留在任务结果里，台账只留比得过的那一屏。

- 排序按指标（夏普 / 年化 / 最大回撤 / 卡玛）；**算不出来的指标沉到底部，不伪装成 0**；
- 备注是台账的意义：数字记录结果，备注记录为什么放弃它；
- 对比页的"载入"把历史实验变成本次的对比变体——翻旧账是为了接着用，不是为了怀旧。

### 参数网格

二十组配置意味着二十次点击、二十次机会打错一个数字，而且不留记录。网格一次提交跑完
所有组合：每组都进实验台账，表格按指定指标排名，最优那行可一键载入为对比变体。

- **上限 200 组，提交前就校验**：200 次回测是几分钟，20000 次是一整夜，而两者的差别
  只是一个按键。超限时在开始之前拒绝，而不是跑了半小时才停。
- 权重方法也是一个维度（可多选），与参数做笛卡尔积；只有方法确实在变时，配置名才带上
  方法名——否则每行都写"等权"，参数本身反而更难读。
- **它是粗筛，不是优化器**：网格能指出值得细看的区域；用自己的最优结果给一次扫描排名
  会高估那个结果（多样本下的最大值不是期望）。所以每行都留档，供事后检验而非直接采信。

### 数据集寻址

不接受任意路径。后端启动时扫描出注册表，前端只传**键**：

- `sample:<stem>` → `data/sample/<stem>.csv`
- `raw:<provider>` → `data/raw/<provider>/daily`

既避免路径遍历，也让"这份数据是什么"始终可见。

## 关键实现决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 计算位置 | 全部在库里，接口只序列化 | 避免两套真相 |
| 状态存放 | 磁盘，无数据库 | 重启无损、无需迁移、与研究文件同一真相 |
| 写操作 | 只有采集一条 | 界面不该悄悄改写数据 |
| 前端构建 | 无（原生 JS + SVG） | 离线可用、安装成本低；规模失控时再引入 Vite |
| 图表库 | 手写 SVG path | 不引 CDN，内网可用；曲线需求只有折线与面积 |
| 长任务 | 线程池任务 + 轮询 | 慢任务不能占住请求线程，详见「长任务」 |
| 并发 | 不做保护 | 触发采集有进程内锁的余地，但第一版先明确「单用户工具」 |

## 取舍与限制（诚实清单）

- **队列是单进程的**：线程池 + 内存状态，多进程部署需要真正的队列（Celery / RQ）。
  重启后列表从归档读回，但只有本进程跑过的任务才有实时进度。
- **取消是协作式的**：`DELETE /api/jobs/{id}` 只置位一个标志，正在进行的那一次请求仍会跑完。
  实测 1500 标的的补数在取消后于第 1 个标的位置停下——不是立刻，但不会继续拉完 1500 个。
- **前端无框架**：三个视图约 400 行 JS 是可维护的上限；再加视图就该引入构建与组件化。
- **无作业队列、无进度反馈**：采集补数请求可能跑几十秒，期间无进度条。
- **无用户/权限**：默认只监听 `127.0.0.1`。暴露到局域网等于把本地数据和采集能力开放出去。
- **不做参数搜索 UI**：只支持手动列举变体，避免一键过拟合。
- **无实验归档浏览**：`reports/` 目前只有采集报告 JSON，实验归档（批次 I）尚未落地。

## 原型状态（本次已实现）

- 后端 18 个端点全部可用，27 条 API 契约测试覆盖（含 404 / 400 / 422 分支、任务取消与归档恢复）；
- 前端四个视图 + 侧栏「最近任务」+ 对比页「参数网格」与「历史实验」（排序、备注、载入为变体）；
- 回测、对比、采集三条慢路径都走任务队列：提交 202 → 轮询进度 → 取结果；
- 实测（样例数据 3 标的 × 504 日，等权 + 收盘成交）：
  - 回测任务：夏普 0.692，706 笔交易（未开换手控制）；
  - 对比基线 vs `buffer=0.05`：692 笔 vs 114 笔，夏普 −0.112 vs −0.116（换手降了，收益也降了，
    这正是要让人看见的代价）；
  - 1500 标的的补数触发取消后，在第 1 个标的位置停下（`stopped after 1/1500`）；
  - `/` 与全部 `/api` 端点在 TestClient 与真实 uvicorn 下均验证通过。
