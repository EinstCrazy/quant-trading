# 代码补全与中文名称

> 这一页回答：为什么屏幕上只有 600519，名字去哪了？

## 问题不在 UI，在数据层

工具里每一屏都是代码：选股名单、回测标的、指标查询。人记的是「贵州茅台」，
机器要的是 `600519.SH`，中间那层翻译一直缺失——而且**数据本来就有，只是被丢掉了**：

| 数据源 | 原始调用 | 原本拿到的 | 之前保留的 |
| --- | --- | --- | --- |
| baostock | `query_all_stock(day)` | `[code, tradeStatus, code_name]` | 前两列 |
| akshare | `stock_info_a_code_name()` | `code` / `name` | 只留 `code` |

两个适配器都在同一次请求里拿到了名称，`list_symbols()` 只要代码，名称就被扔了。
所以这不是新请求，是**把已有的列留下来**。

## 名称表：按需刷新，不是每次请求

全市场清单调用很慢（akshare 几十秒，baostock 约 8 秒），而名称几乎不变——公司改名
比公司上市少见得多。所以落一张表，用到时才刷：

```bash
quant-symbols --refresh                # 拉一次，写 data/universe/names.parquet
quant-symbols                          # 表的状态：多少只、什么时候刷的
quant-symbols -q 茅台                  # 按名称或代码查
quant-symbols -q 3007 --limit 3
```

```text
$ quant-symbols -q 茅台
  600519.SH  贵州茅台

$ quant-symbols -q 3007 --limit 3
  300700.SZ  岱勒新材
  300701.SZ  森霸传感
  300702.SZ  天宇股份
```

实测 baostock 全市场 **7441 只、8 秒**（含指数——`query_all_stock` 返回所有证券，
不只股票）。

## 接口

```http
GET /api/symbols?q=茅台&limit=8
```

```json
{
  "items": [{"symbol": "600519.SH", "name": "贵州茅台"}],
  "available": true,
  "total": 7441,
  "updated_at": "2026-11-03T06:28:34"
}
```

接口只读磁盘，不触发抓取：打字间隔是几百毫秒，全市场查询是几十秒，把它放在
按键路径上等于让输入框卡死。

`available: false` 表示名称表还没建。这不是错误——输入框照样能填代码，只是补不出
候选，前端据此提示 `quant-symbols --refresh`，而不是静默给一个空下拉。

## 排序：先代码，后名称

```
rank -1  完整代码命中          600519.SH → 600519.SH
    0   裸代码完全相同        600519    → 600519.SH
    1   代码前缀              6005      → 600519.SH
    2   名称前缀              宁德      → 宁德时代
    3   名称子串              银行      → 平安银行 / 招商银行 / 兴业银行
```

同分按裸代码排序，所以「银行」会先出 000001 再出 600036，顺序稳定可预期。
敲了六位数字的人要的是那一只，不是"所有含这串数字的东西"——这是排序存在的理由。

空查询返回空。一个敲下第一个字符就弹出五千行的下拉，比什么都不弹更难用。

## 交互

```text
输入 600519 ──200ms 防抖──▶ GET /api/symbols ──▶ 下拉 8 条
                                              ├ 600519.SH  贵州茅台
                                              └ ...
↑ ↓ 选择    Enter 填入    Esc 关闭
```

四个刻意选择：

- **200ms 防抖 + `seq` 丢弃过期响应。** 打字比网络快，`6005` 的响应可能在 `600519`
  的响应之后才回来；不丢弃的话，下拉会退回到上一次的结果。这是补全控件最容易忽略
  的一处。
- **菜单挂在 `body` 上用 `fixed` 定位。** 表单是 flex 布局，插一层 wrapper 会挤动
  兄弟元素。挂在 body 上只算一次 `getBoundingClientRect()`。
- **`mousedown` 而不是 `click`。** `blur` 先于 `click` 触发，等 click 时菜单已经关了。
  多选输入框（采集页的标的列表）同样处理：替换最后一个逗号后的片段，并补回 `", "`，
  方便接着敲下一只。
- **`MutationObserver` 补挂，而不是初始化时绑一次。** 采集页每次刷新都用 `innerHTML`
  整块重绘表单，绑在元素上的监听会随之消失。`WeakSet` 保证同一个输入框只增强一次。

## 边界

- **不做拼音、不做模糊纠错。** `maotai` 查不到「贵州茅台」，`茅台` 里打错一个字也查
  不到。加拼音要引入词库，收益不如前缀匹配直接。
- **指数混在候选里。** baostock 的 `query_all_stock` 返回全部证券，`000001.SH` 是
  上证指数、`000001.SZ` 才是平安银行——代码相同、后缀不同，靠后缀区分。
- **名称表是快照。** 新上市、改名、退市都不会自动反映，取决上次 `--refresh` 是什么
  时候。表的状态行会打出更新时间。
- **空表拒绝写入。** `universe.save({})` 直接抛错：用一张空表覆盖好表，会让所有输入
  框悄悄退化成只能补代码，而界面上看不出任何异常。
