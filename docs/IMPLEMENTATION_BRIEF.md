# 量化研究实现总纲

本文档把项目现状、目标态、阶段交付、投入和实施路径整理到一处，作为后续拆任务和讨论取舍的入口。具体模块任务仍以 [ROADMAP.md](ROADMAP.md) 为准。

## 一、项目定位

建设一套面向个人或小团队的离线量化研究工作台：研究者可以把行情数据和策略假设转化为可复现的回测结果，并判断策略是否值得继续研究或进入纸面验证。

本项目当前不以生产交易系统为目标。范围明确为：

- 包含历史数据处理、策略信号、仓位构建、日频回测、绩效分析、实验归档和研究报告。
- 可在后续阶段增加模拟或纸面验证，但不自动连接券商、不提交真实订单。
- 暂不处理实时行情、Tick 级高频交易、生产部署、账户风控和多用户权限。
- 研究结论必须说明数据、成交和成本假设；历史表现不代表未来收益，也不构成投资建议。

## 二、最终态

最终交付不是“有很多策略”，而是一个可信、可重复使用的研究闭环：

```text
研究假设
  → 数据校验与对齐
  → 信号 / 因子
  → 目标仓位与约束
  → 含成本回测
  → 绩效、风险与稳健性分析
  → 可复现实验记录与报告
  → 继续研究、否决或纸面验证
```

达到最终态时，用户应能：

- 用配置指定数据范围、策略参数、基准、资金和交易成本，运行一项实验。
- 检查数据质量、信号时点、仓位变化、成交、费用、现金和净值，而不只看到一个收益数字。
- 通过样本外或 walk-forward、基准与随机对照、参数敏感性分析判断结果是否稳健。
- 凭实验编号和代码版本复现结果，并比较不同实验。
- 获取包含净值、回撤、收益风险指标及关键假设的报告。

**最终态验收标准**：一个新策略可按既有契约接入；完整实验可从配置运行；关键中间结果可检查；结果可重复；对前视偏差、成本遗漏和样本外失效有自动检查或明确提示。

## 三、当前起点

当前项目处于脚手架阶段，已有：

- CSV 单标的收盘价加载和基础校验。
- 双均线 long-only 信号。
- 年化夏普和最大回撤两个指标。
- YAML 默认配置，以及 pytest / ruff 工程配置。

主要断层：组合与回测尚未实现，配置中的成本参数尚未被执行层消费，指标测试和实验归档也不完整。因而当前可以演示“数据 → 信号 → 手工收益计算”，还不能把回测结果作为可信的策略判断依据。细节见 [README.md](../README.md) 和 [ROADMAP.md](ROADMAP.md)。

## 四、中间态与阶段门槛

| 阶段 | 中间态 | 主要交付 | 退出 / 验收门槛 |
| --- | --- | --- | --- |
| 0. 工程可协作 | 改动可测试、可回溯 | Git、CI、格式与测试检查、基础类型检查 | 新环境能安装并通过测试；每次改动可自动验证 |
| 1. 数据可研究 | 输入数据有统一契约 | 配置加载、多标的面板、数据质量检查、样例数据 | 数据来源、频率、时区、复权和缺失处理可追溯 |
| 2. 单标的最小闭环 | 一条策略能得到可信净值 | 信号滞后、固定仓位、日频回测、手续费与滑点、账本、核心指标 | 零成本可与手算一致；成本会反映到结果；无前视偏差 |
| 3. 多标的组合 | 信号能变成受约束的组合 | 权重分配、持仓和杠杆约束、换手控制、多标的回测 | 权重约束通过测试；交易和组合收益可解释 |
| 4. 研究结论可信 | 策略经过稳健性检验 | 基准、样本外 / walk-forward、参数敏感性、随机对照、扩展指标 | 结果不依赖单一参数尖峰或单段行情；结论包含风险和局限 |
| 5. 实验可复用 | 运行、比较和复现形成习惯 | 实验配置、结果归档、实验编号、比较表和报告 | 历史实验可复现，报告包含参数、数据区间和代码版本 |
| 6. 纸面验证（可选） | 离线研究结果与模拟运行对照 | 定时数据更新、信号记录、模拟成交与偏差监控 | 连续运行和异常处理经过验证；仍不触发真实下单 |

每阶段先做能验证关键假设的最小版本。若阶段门槛未达到，不应仅因回测收益好看就扩展策略数量或进入下一阶段。

## 五、建议实施路径

推荐的主路径是先打通纵向闭环，再扩展横向能力：

1. **固化研究边界与工程底座**：确认只做离线研究与纸面验证；建立版本控制、CI 和基础测试。
2. **规范数据和实验输入**：接入配置；先支持可靠的单标的 CSV，再扩展到多标的面板和缓存。尽早固定复权、时区、交易日历和缺失值规则。
3. **定义最小信号与仓位契约**：现有均线策略作为样例；加入统一滞后机制。先用固定仓位，不急于开发复杂因子库或优化器。
4. **交付最小回测引擎**：日频、明确成交时点、手续费和滑点；输出现金、持仓、交易流水与净值。用小型合成数据和手算结果验证。
5. **形成评估门槛**：补齐收益、风险、回撤和基准指标，再加入样本外、滚动验证和参数敏感性分析。
6. **扩展组合和策略**：只有最小闭环可信后，再投入多标的权重分配、约束、换手控制和策略族扩展。
7. **自动化归档与呈现**：把配置、数据说明、代码版本、指标及图表绑定到实验编号；最后制作标准报告和 notebook 模板。
8. **按需开展纸面验证**：仅在研究与稳健性门槛通过后评估，另行定义运行监控和停止条件；本项目不因此自动扩展到实盘。

**优先原则**：最小回测闭环优先于大量策略；数据与执行假设优先于图表；样本外验证优先于参数寻优；研究结论优先于工程规模扩张。

## 六、投入估算

以下为相对投入，不是日历工期承诺。它假设先支持日频、本地数据、单一研究者；数据授权、质量和交易日历不确定性可能显著增加投入。

| 工作流 | 相对投入 | 主要成本来源 | 可后置内容 |
| --- | --- | --- | --- |
| 工程底座 | 低 | Git、CI、测试与代码规范 | 复杂部署、多人权限 |
| 数据层 | 中至高 | 数据源差异、复权、停牌、跨标的对齐和质量诊断 | 实时接入、昂贵供应商、多资产类别 |
| 最小回测闭环 | 中 | 成交时序、仓位账本、成本建模和边界测试 | 高频撮合、复杂订单类型、税务模型 |
| 绩效与稳健性 | 中 | 基准对齐、样本外切分、统计检验和结果解释 | 高级归因、复杂风险模型 |
| 多标的组合 | 中至高 | 约束求解、暴露管理、容量和换手控制 | 复杂优化器、行业数据依赖 |
| 实验管理与报告 | 中 | 结果格式稳定、运行追踪、图表和模板维护 | Web 平台、协作服务、云端编排 |
| 纸面验证 | 中至高 | 数据更新、运行调度、告警、漂移与故障处理 | 券商连接和真实资金交易 |

**人员能力**：核心工作可由一名熟悉 Python / pandas、回测方法和测试的工程研究者分阶段完成。若数据源、资产类别或研究流程增加，需补充数据工程、统计研究或运维能力。数据授权和市场数据本身的采购成本需单独评估，不包含在代码投入中。

## 七、范围与技术取舍

- 先采用 pandas / NumPy 和透明的日频执行规则；只有基准测试证明性能成为瓶颈后再优化或引入框架。
- 回测优先可审计性：明确何时生成信号、何时成交、价格如何取值、成本如何计算。
- 不以高回测收益作为唯一成功指标；实现正确性、稳健性、可复现性和研究效率同等重要。
- 不提前建设 Web 前端、实时服务、云部署或实盘执行，除非用户和研究流程已证明确有需要。
- 区分“研究工具”和“交易系统”：纸面验证不是自动实盘的前置承诺。

## 八、主要风险与应对

| 风险 | 可能后果 | 应对方向 |
| --- | --- | --- |
| 前视偏差或错误成交时点 | 回测收益虚高 | 统一信号滞后约定，以手算样例和测试锁定时序 |
| 复权、停牌或成分股数据不完整 | 收益和可交易性判断失真 | 保存数据元信息，逐步补齐交易日历和历史标的池 |
| 手续费、滑点和容量被低估 | 策略落地后收益消失 | 默认保守成本，报告换手及成本敏感性 |
| 参数过拟合与多重试验 | 样本内有效、样本外失效 | 预留样本外数据，做 walk-forward、随机对照和敏感性检查 |
| 过早扩张策略与功能 | 研究结果不可比较、维护负担上升 | 先验收纵向最小闭环，再扩大策略和资产范围 |
| 数据许可和来源不明确 | 无法复现或无法合规使用 | 记录来源、授权与使用限制；采购另行决策 |

## 九、待确认的产品决策

在扩大 P1 数据层和 P3 组合能力之前，建议明确：

- 首批资产类别和市场：股票、ETF、期货或其他；是否只做日频。
- 研究方式：纯单标的时间序列，还是尽快支持横截面多标的策略。
- 数据源、历史覆盖范围、复权质量、授权预算和更新方式。
- 回测默认成交假设：次日开盘、收盘或其他；无法成交与停牌如何处理。
- 最小可用结果：只需本地 Python API，还是需要 CLI、Notebook 或报告模板。
- 纸面验证是否属于本项目目标，以及进入该阶段前的风险门槛。
- 可投入人力、每周可用时间和首个阶段的验收日期。

这些决策会影响投入和先后顺序；在答案明确前，保持本总纲中的轻量、离线、日频默认假设。
